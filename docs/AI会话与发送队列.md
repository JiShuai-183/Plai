# AI 会话与发送队列

本轮依据 2026-11-06 用户逐项确认的方案实现。功能位于 AI Tab 内，不增加主导航或第三方依赖。

## 会话入口

- 冷启动后首次进入 AI 显示会话起始页。使用中切换 Tab、短暂切后台仍保留当前聊天。
- 起始页提供新建、标题搜索、最近消息摘要和时间。置顶优先，其余按活跃时间倒序。
- 新建只进入编辑界面；首次发送时建立会话。标题取首条正文前 24 个 Unicode 字符，纯图片为“图片对话”，后续不覆盖手动名称。
- 单条菜单提供重命名、置顶和删除；批量管理只提供删除。全选针对当前搜索结果，修改搜索条件清空勾选。
- 运行中或等待操作确认的来源会话不可删除；删除其他会话前提示其排队消息数量，事务删除会话、消息和相关队列项。

## 草稿与排队

- 草稿的文字与图片按会话隔离，保留在当前页面生命周期内，不承诺进程退出后的普通草稿恢复。
- 所有会话共用全局 FIFO 队列。同一时刻只运行一条消息，其他会话可以继续编辑和排队。
- 入队冻结来源会话、正文和图片。用户消息与队列记录在同一事务插入；附件复制到应用私有持久目录。
- 未开始的消息可以取消，或撤回到输入框修改后重新排到队尾。撤回编辑前暂存输入框原草稿；重新发送或取消编辑后恢复。
- 排队任务显示在底部输入框上方的叠层面板，提供撤回修改与取消发送图标；开始处理后沿用原消息气泡与进度行。撤回时保留输入框实例、焦点和输入连接，避免键盘收起后重弹。
- 真正执行时重新读取历史和本地状态。未来排队消息不进入当前请求上下文；回复按来源请求归组显示。
- 页面通过独立 `AiQueueController` 观察运行状态，流式文本单独监听，不随 token 重建整页。

## 确认、失败与恢复

- 写操作始终需要确认。当前会话可直接显示确认面板；来源会话在后台时只显示导航提示。
- “稍后确认”保留草稿并暂停队列，允许切换会话或继续排队。“执行选中项”或“全部跳过”后继续。
- 网络或工具执行失败暂停队列，由用户重试或跳过；已成功操作不会因重试整个模型请求而再次生成。
- 已验证提案在确认前保存。每项写操作执行前记录意图，执行后保存结果；编辑后的恢复提案与被替代提案一起更新。
- `succeeded` 操作不重放；`running` 或 `unknown` 表示结果可能已生效。中断恢复要求先核对，再对未完成项重新确认。
- 数据库写入与业务副作用之间不存在跨模块原子事务。进程若在业务写入后、结果检查点提交前退出，该项必须人工核对，不能声称一定未执行。
- 重启后，未开始项等待手动继续；原运行项和待确认项标记为中断。不会在重启时自动发送或自动重放写操作。
- 运行期间发生读取错误后的“重新加载”只重读队列，不把仍活跃的请求当作重启遗留项；执行中的请求不可跳过。
- 运行依赖应用进程；没有增加 Android 前台服务或系统保活保证。普通 `.plai` 备份沿用原范围，不包含运行队列。

## 实现入口

| 文件 | 职责 |
| --- | --- |
| `lib/features/ai/ai_page.dart` | 起始页/聊天切换、草稿、确认及队列状态交互 |
| `lib/features/ai/ai_sessions_view.dart` | 搜索、摘要、单条管理、批量删除 |
| `lib/features/ai/ai_queue_controller.dart` | 全局串行调度、暂停、撤回、恢复、删除协调 |
| `lib/features/ai/ai_queue_providers.dart` | 应用级依赖组装，执行时构造请求 |
| `lib/features/ai/ai_conversation_controller.dart` | 单条消息的模型循环、提案确认、逐项执行日志 |
| `lib/features/ai/ai_queue_attachments.dart` | 稳定附件副本、编码与受限回收 |
| `lib/data/repositories/chat_queue_repository.dart` | V6 持久队列及事务操作，契约见数据层接口文档 |

任务保存、提醒及课表重排继续复用原有业务服务；只读/写工具通过 `AiToolContext` 访问应用级 provider，不持有页面的 `WidgetRef`。
