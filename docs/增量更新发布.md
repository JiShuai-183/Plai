# Android 增量更新发布

增量只是完整 APK 之外的可选下载方式。完整 APK、原有四道安装闸门、通知资源检查、原子发布和保留最新五版的规则继续生效。客户端遇到基线不匹配、补丁下载或合成失败时使用完整 APK；旧客户端忽略新增字段，继续全量更新。

## 本地准备

使用 Python 3.9–3.13 创建隔离环境，再安装固定依赖：

```powershell
python -m venv build/delta-venv
build/delta-venv/Scripts/python.exe -m pip install -r tool/requirements-delta.txt
```

`publish_plai_update.ps1` 优先使用这个环境，也可通过 `-PythonExe` 指定其他 Python。缺少 Python、依赖或生成器验证失败，会明确告警并仅准备完整 APK。

目标 APK 须放在仓库 `build/` 目录内才能生成补丁。重复准备会在核实路径属于 `build/` 后重新生成本工具命名的 `.patch` 和 `.patch.json`；目录外的既有补丁与 sidecar 不会被删除，工具告警并仅准备完整 APK。

先按照既有流程构建、验签并命名目标 APK。准备基线时必须保留上一正式版实际发布的完整 APK，不能使用同版本的另一次构建替代。基线的实际 SHA-256 和大小必须与上一正式清单一致。

下面的命令只生成本地清单和可选补丁，不连接 SSH、不上传。省略 `-BaseManifest` 时，会通过 HTTPS 读取当前线上 `latest.json`；需要完全离线预览时，显式提供之前保存的正式清单：

```powershell
./tool/publish_plai_update.ps1 -PrepareOnly `
  -Version 2.4.1 `
  -AndroidApk ./build/app/outputs/flutter-apk/Plai-android-2.4.1.apk `
  -BaseApk ./build/Plai-android-2.4.0-online.apk -BaseVersion 2.4.0 `
  -BaseManifest ./build/base-2.4.0.json `
  -ManifestOutput ./build/latest-2.4.1.preview.json `
  -Notes '本次更新内容' -Announcement '升级后公告'
```

示例版本仅说明参数，不代表这些版本已发布。`release_plai.ps1 -PrepareOnly` 则包括构建、测试与安装闸门，并把预览清单放到 `build/app/outputs/flutter-apk/latest-<版本>.preview.json`，无需私钥或 `gh`。真正发布仍须获得当次授权；不会因为上一次发布曾获授权而自动开始。

## 补丁准入条件

发布工具不接受外部 delta JSON，而是从本次读取的实际文件重新生成：

1. `BaseVersion` 必须等于上一正式清单版本；基线完整 APK 的哈希和大小逐项匹配清单。
2. 使用 Android build-tools 验证新旧 APK 均为 `com.plai.plai`、具有既有目标签名和 v2 签名，实际 `versionName` 与参数一致，且目标 `versionCode` 更大。
3. 调用 `create_apk_delta.py --old ... --new ... --output ... --verify`。生成器实际应用补丁并逐字节比较目标完整 APK。调用方再次核对基线和目标在生成期间没有改变，并从实际补丁计算大小和哈希。
4. 补丁必须小于完整 APK 的 80%，并且至少节省 1 MiB。未达到门槛、缺少合适基线或生成验证失败时，明确告警，仅发布完整 APK。已确认的新旧 APK 若出现签名、包名、实际版本冲突或 `versionCode` 不递增，则立即停止，不能作为可选补丁错误降级处理。

第一版仅支持一个基线直达本次目标，不发布多跳补丁链。补丁文件采用 `Plai-android-<基线>-to-<目标>.patch`，清单路径由工具固定生成，始终位于 `releases/<目标>/`。

## 清单兼容性

`schemaVersion` 保持 1，`assets.android` 原有 `name/path/size/sha256` 始终描述完整 APK。仅在上述检查全部通过时，增加可选的 `delta` 对象：

```json
{
  "format": "plai-bsdiff-gzip-v1",
  "fromVersion": "2.4.0",
  "fromSha256": "上一正式完整APK的64位小写SHA256",
  "fromSize": 63826087,
  "name": "Plai-android-2.4.0-to-2.4.1.patch",
  "path": "releases/2.4.1/Plai-android-2.4.0-to-2.4.1.patch",
  "size": 123456,
  "sha256": "本次实际补丁的64位小写SHA256"
}
```

这是字段示例，不可直接作为发布元数据。生成器的旁路 `.patch.json` 用于诊断；发布工具不直接相信或透传它。

## 获授权后的发布

`publish_plai_update.ps1` 的现有发布命令可追加 `-BaseApk`、`-BaseVersion` 和可选的 `-PythonExe`。真正发布禁止传入 `-BaseManifest`，始终重读线上最新清单来核对上一正式版；离线预览不能代替这一步。

全量发布同样须验证目标包身份及版本递增。新清单在顶层记录从 APK 实际读取的 `versionCode`；旧清单没有该字段时，工具使用与清单大小、哈希完全匹配的 `BaseApk` 读取真实版本号，或下载清单所指的旧完整 APK，再核对字节、签名、包名和实际版本。无法核实、字段冲突或目标 code 未递增时，在上传前停止。仅做本地 `PrepareOnly` 不代表已经通过正式发布的线上版本递增核验。

脚本将完整 APK、可选补丁和清单上传到同一个 staging 目录，核对所有文件的 SHA-256 以及 APK/补丁的实际大小，再整体移入全新的版本目录并最后切换 `latest.json`。原版本目录不得覆盖。清理仍按语义版本保留最新五版，补丁随其目标版本目录保留或清理。

`release_plai.ps1` 同样接受基线参数，但不扩展认证方式：正式一键发布要求已安装并登录 `gh`，缺少时在构建和上传前停止。没有 `gh` 时，可在明确授权后由操作者使用发布脚本与已审核的 GitHub REST 流程分别完成三同步。

发布后仍须实际下载完整 APK，验证本地、清单、公网字节的大小和 SHA-256 一致，并检查 Range 206；存在 delta 时还应下载补丁核对大小和哈希，再用已知基线合成核验目标完整 APK。客户端最终安装的仍是原始签名完整 APK。

## 工具检查

```powershell
./tool/tests/publish_delta_tests.ps1
./tool/tests/prepare_delta_repeat_test.ps1
```

第一组测试隔离 SDK、Python、HTTP 和 SSH 边界，包含 40 项检查，覆盖线上/离线基线读取、身份与哈希不匹配、生成失败、补丁收益不足、全量四字段兼容、全量发布版本闸门、增量预览、目录外文件保留、staging 上传和校验、禁止覆盖、五版保留及 CRLF 归一化。第二组只隔离 Android SDK 边界，真实调用 Python 生成器及 `--verify` 两次，确认第一次留下的 sidecar 不会让第二次静默降级；两组均不联网、不上传。编解码正确性另由生成器与客户端测试验证；准备模式可配合已发布的真实 APK 做本机集成验证。

2026-11-07 本机离线验证记录：已发布的 2.3.6 APK（63,039,583 字节）到 2.4.0 APK（63,826,087 字节），生成补丁 5,002,463 字节，约为完整 APK 的 7.84%；含实际验签、生成和完整还原比较的准备过程耗时约 72.4 秒。该补丁仅用于本机验证，未追加到已经发布且不可覆盖的 2.4.0 目录。其他版本的收益和耗时必须重新实测。

客户端全量 917 项 Flutter 测试通过，Python 7 项测试通过；真实补丁经纯 Dart 流式解码后与目标 APK 的 SHA-256 完全一致，本机 Windows JIT 还原约 5.2 秒。Android release 预览构建通过证书、v2 签名、包名和通知资源检查，63,858,855 字节，相比同机已发布 2.4.0 包增加 32,768 字节。预览版本仍为 2.4.0+25，只用于本地编译验证，不满足正式发布的版本递增条件；官方命名 APK 未覆盖，预览包未上传或安装。下一正式版必须先递增版本，经全量通道向旧客户端交付该能力。
