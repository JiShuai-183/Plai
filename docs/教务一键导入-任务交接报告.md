### 2.1 新增：郑航教务课表一键导入

**入口**：课表页 AppBar 左上角 `Icons.sync` → 命名路由 `AppRoutes.eamsImport`。

**代码**（全部在 `lib/features/timetable/eams/`，归 **plai-timetable**）：

| 文件 | 职责 |
|---|---|
| `eams_client.dart` | 网络层：登录（salt + SHA1）、Cookie jar、取 `ids` / `semester.id` / 课表响应体 |
| `eams_parser.dart` | 解析层：**纯函数**，教务 JS 响应 → 中间模型 |
| `eams_import_models.dart` | 中间模型 |
| `eams_import_service.dart` | 编排：全量对账 `plan()` + 施加变更 `import()` |
| `eams_import_page.dart` | UI：输入 → 拉取 → 变更清单（逐项勾选）→ 确认导入 |

**实施计划书（含全部实测接口契约）**：`docs/教务一键导入-实施计划.md` —— **改这个模块前必读**。

**关键设计**（改动前务必理解，否则容易改坏）：

1. **以教务课表为基准的全量对账**（计划书 §5）。`plan()` 按 merge 去重键
   `(name, weekday, startWeek, endWeek, startPeriod, endPeriod)` 把「教务课程」与
   「本学期现有课程」配对，产出**将新增 / 将更新 / 将删除**三类变更。
2. **`import()` 的 `plan` 与 `selectedChangeKeys` 都是必填** —— 有意设计，不给
   「绕过预览直接写库」留口子。一条都没勾时**抛 `ArgumentError`**（fail-closed，
   不静默 no-op）；界面在此时禁用确认按钮。
3. **未勾选的「将新增」必须从交给 `importJson` 的课程列表里剔除**
   （`_buildImportJson` 的 `skipKeys`），否则 `merge` 照样会插进去。
   未勾选的「将更新 / 将删除」无需剔除：前者本地同键记录仍在（merge 会跳过），
   后者本就不在教务列表里。
4. **曾有的「记账式」方案已废弃**（记「哪些课是我导入的」）。该信息必然不完备
   —— 用户手动加过的课、用「导入导出」页导过的课都不在记账里 —— 导致两个实测故障：
   「教务改了客户端不跟着变」与「同键旧记录删不掉、产生重复」。计划书 §5.1 有完整说明。
5. **凭据独立保存**：用户选择记住后，页面经 `IEamsCredentialsRepository` 写系统安全存储。
   `eams.username` 仅兼容旧数据，保存/清除时移除；导入服务仍不写任何 settings 键。

## 3. ⚠️ 本轮亲身踩的坑（**最省时间的部分**）

### 3.1 热重载 vs 热重启：给类**加字段**后必须热重启

真机上出现 `_TypeError: type 'Null' is not a subtype of type 'Duration'`，
排查数轮才发现：**给类新增字段后，Dart 热重载（小写 `r`）不会给已存在的实例补初值**，
读该字段得到 `null`。

**判据**：`eams_import_page.dart` 的改动（**方法体**）生效了、`eams_client.dart` 的改动
（**新增字段**）没生效 —— **两者的差别就是答案**。

**教训**：静态分析 + 单测无法发现这类问题（测试里对象是新构造的，初值正常）。
**给类加字段后，让用户按 `q` 退出再 `flutter run`**，别只说「热重载一下」。

### 3.2 `testWidgets` + sqflite：默认工厂会把用例挂死

`sqflite_common_ffi` 默认的 `databaseFactoryFfi` 把 SQLite 跑在**后台 isolate**（真实异步 I/O）。
而 `testWidgets` 的 body 跑在**假时钟 zone**，真实 I/O 的 Future 永远不完成
→ `await db.database` 卡死，用例无限期挂起，**`--timeout` 也不生效**。

**症状**：用例名打印出来后卡住 90s+ 不报错。

**解法**：widget 测试里建库改用 **`databaseFactoryFfiNoIsolate`**（同进程）。
见 `test/features/timetable_page_test.dart` 的 `_createTestDataInProcess()`。

> 注意：`test/data/test_helpers.dart` 的 `TestData.create()` 用的是**默认工厂**，
> 在 `test()`（单元测试）里没问题，**在 `testWidgets()` 里会挂**。

### 3.3 前台跑长命令会「卡死对话」

`flutter test` 等长命令若放在**前台**跑且接了 `| tail`，输出会被缓冲到结束才吐，
期间整轮对话无响应 —— 表现为「卡死」。用户会以为工具坏了。

**做法**：长命令一律 `run_in_background: true`，且**不要接 `tail`/`head`**（会缓冲），
直接读输出文件。真要截断也等跑完再截。

另：反复打断/杀测试进程会留下**孤儿 `flutter_tester.exe`**，它锁住
`build/native_assets/windows/sqlite3.dll`，导致下一次 `flutter test` 报
「Flutter failed to delete file」。解法：`taskkill //F //IM flutter_tester.exe`。

### 3.4 `git log -S` 不是「含该串」的检查

校验隐私清理时，我用 `git log -S"<某个真实教师名>"` 判断「哪些提交仍含该串」—— **用错了**。
`-S`（pickaxe）找的是**改动过该串出现次数的提交**，命中的恰是**删掉它**的那个提交，
于是误报「还有残留」。

**正确做法**：逐个提交检查树内容
```bash
for c in $(git rev-list A..B); do git grep -q "串" "$c" -- . && echo "$c 含"; done
```

### 3.5 验证步骤不得对被测对象做预处理（老坑，本轮又犯）

`AGENT_ONBOARDING.md` §6.5 记过这条，本轮**又踩了一次**：实施计划书 §2.2 曾写
「门户首页服务端直出 `semester.id` / `ids`」，依据是用户 `Ctrl+S` 保存的页面 ——
而**那是浏览器渲染后的 DOM**，参数是 JS 事后注入的。服务端原始响应里根本没有。

这个错误结论**同时写进了代码与文档**，导致真机验收卡在取参这一步、多花数轮排查。

**规则**：要么用真实输入测，要么明确把预处理当作被测逻辑的一部分去测。
**「用浏览器保存的页面」≠「服务端的响应」。**

### 3.6 交互式改动的验证，必须用真实响应

同上一条的具体化：教务系统的接口契约**只能靠真机实测**。
本项目已经积累了一批实测结论（计划书 §2），**改网络层/解析层前先读，不要重新推断**。

## 4. 教务模块的边界（改它之前必读）

- **归属**：`lib/features/timetable/eams/**` 与 `test/features/eams/**` 归 **plai-timetable**。
  路由 `lib/routes/**` 归 **plai-scaffold**。跨模块改动交主会话协调。
- **明文 HTTP 是必需的**：该站 HTTPS 实测不通。`network_security_config.xml` **只对
  `jwglxt.zua.edu.cn` 单域名放行明文**，全局仍禁止。**不要**改成全局
  `usesCleartextTraffic`，也不要删掉那个域名例外（删了功能直接废）。
- **登录前有 1 秒最小停留**（`EamsClient.defaultLoginFormDwell`）：服务端有「防过快点击」
  闸门，不等待则登录 **100% 失败**，且返回文案长得像「密码错」。**这不是重试**，
  与「绝不自动重试登录」（防锁号）的约束不冲突。**不要删**。
- **`res/raw/keep.xml` 不能删**：删掉会让 release 包的**所有提醒崩溃**
  （详见 `docs/提醒送达问题交接报告.md` §5）。
- **节次时间沿用 Plai 默认模板前 10 节**；开学日取不到自动值（`dataQuery` 只给学期
  id / 学年 / 学期序，**没有起止日期**），由导入页显示 + 手动改。

1. **不要自行 `git push` 或发布**。26 个本地提交由用户决定何时推送。
