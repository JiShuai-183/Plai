# 课表一键导入（郑航教务）· 实施计划

> 状态：**已与用户敲定方案，待实施**。创建：2026-09-19。
> 目标系统：郑州航空工业管理学院教务系统 `http://jwglxt.zua.edu.cn`（Beangle/EAMS 系）。
> 本文是**实施期工作文档**；落地后其结论应归并进 `README.md` 版本记录与 `AGENT_ONBOARDING.md`，本文可删。

## 1. 目标与边界

**目标**：课表页左上角一个「更新」图标 → 输入学号/密码 → 一键拉取教务课表并导入 Plai 当前学期。

**用户已拍板的四条**

| # | 决策 | 理由 |
|---|---|---|
| 1 | 课表页 HTML 样本由用户在自己 PC 浏览器抓取后交付 | 不接受在应用内代持凭据做探查 |
| 2 | **密码绝不落盘**，每次手输；仅可记住学号 | 零新增依赖、零泄露面 |
| 3 | 学期/节次「能自动取就自动取」，取不到降级为手填或沿用默认 | 兼顾一键体验与可用性 |
| 4 | **导入到当前学期，且绝不改动用户手动添加的课程** | 见 §5 的记账式方案 |

**明确不做**

- 不做后台自动同步 / 定时刷新 / 静默重拉
- 不做验证码识别（首屏实测无验证码；真出现则提示用户，不硬闯）
- 不做学校改版自愈（改版由解析层单测暴露）
- 不做账号密码持久化
- 不做 iOS 差异处理（本功能仅 Android 侧实测）

## 2. 已确证的接口契约（**均有实测证据，勿重复验证**）

### 2.1 登录（2026-09-19 实测）

```
① GET  /eams/loginExt.action
   → Set-Cookie: JSESSIONID(Path=/eams)、GSESSIONID(Path=/)
   → HTML 内含本轮随机下发的 SHA1 salt：
      form['password'].value = CryptoJS.SHA1('<salt>-' + form['password'].value);

② POST /eams/loginExt.action
   username=<学号>&password=<SHA1(salt + '-' + 明文密码)>
   &needModify=0&session_locale=zh_CN&login_from=login_from&submitBtn=登录
   （必须复用 ① 的 Cookie —— salt 与 session 绑定）
```

- **salt 每次响应都不同**：实测两次 GET 得到 `7ab898f1-…` / `54d85fde-…`。**不可写死**，必须两步走。
- 登录失败：**HTTP 200**，body 多出 `<div class="actionError">…账号或密码异常</div>`。可精确判别。
- 首屏与 1 次失败后**均无验证码输入框**（页面里那个 `refreshCaptcha` 函数是死代码）。

#### ⚠️ ①→② 之间必须间隔 ≥0.5 秒（2026-09-20 补测）

服务端有**防「过快点击」闸门**：登录页 GET 与登录 POST 之间隔得太近会被直接
拒绝，返回 `请不要过快点击`。真机验收时表现为**登录 100% 失败**，且该文案极易
被误读成「密码错」。

用真服务器 + 假学号实测阈值（同一 Cookie 会话）：

| GET→POST 间隔 | 服务端响应 |
|---|---|
| 0s / 0.3s | `请不要过快点击`（被拦） |
| 0.5s / 0.8s / 1s / 2s / 3s / 5s | 正常走登录（回 `账号或密码异常`） |

阈值在 0.3~0.5s 之间。客户端取 **1 秒**（2 倍余量，远低于人的感知阈值），
用 `Stopwatch` 计**真实耗时**（含 GET 自身的网络往返），网络慢时自动少等。
**该等待不是对失败登录的重试**，与「绝不自动重试」的约束不冲突。

### 2.2 取 `ids` 与 `semester.id`

> ⚠️ **本节曾写错并被订正（2026-09-20）。** 原结论称「门户首页 HTML 服务端直出
> `semester.id` / `ids`，正则 `semester\.id=(\d+)&ids=(\d+)` 即可」——
> **错的**。那个结论来自用户 `Ctrl+S` 保存的门户页面，而**那是浏览器渲染后的
> DOM**，参数是 JS 事后注入的；服务端原始响应里根本没有。
> 教训同 `AGENT_ONBOARDING.md` §6.5：**验证时不能拿被预处理过的对象当原始输入**。
> 该错误在文档与代码里同时存在，导致真机验收卡在取参这一步、多花数轮排查。

**两个参数来自两个不同端点（真机探针实测，三重印证）。**

**① `ids` ← `GET /eams/courseTableForStd.action`**

实测该页 200、9605 B，内含 JS 形式的 `"ids","1234567"`。正则：

```dart
RegExp(r'"ids"\s*,\s*"(\d+)"')
```

> 注意：**未登录**时直接访问该页会返回 `error.courseTable.unknown`，故必须
> 在登录之后取。登录后即正常返回。

**② `semester.id` ← `GET /eams/dataQuery.action?dataType=semesterCalendar&empty=false`**

实测响应 4342 B，是一个 JS 对象，含全部学期表（共 53 条，按学年分组）：

```js
semesters:{y00:[{id:43,schoolYear:"2000-2001",name:"1"}, …],
           y26:[{id:297,schoolYear:"2026-2027",name:"1"}]},
yearIndex:"-1", termIndex:"-1", semesterId:""}
```

- **`yearIndex` / `termIndex` / `semesterId` 三个标记位实测恒为空**
  （`-1` / `-1` / `""`，`empty=false` 与 `true` 都一样）—— 门户自身也没靠它们
  选学期，**不能用**。
- 当前学期的判定见 `EamsClient.pickCurrentSemesterId`：优先用门户首页显示的
  文案（如「2026-2027第1学期」）与学期表精确匹配；匹配不到则退回
  「学年 + 学期序最大的一条」（实测末条即当前学期 `id=297`）。

**反面结论：门户首页不含这两个参数。** `homeExt!main.action`（17082 B）与
`homeExt.action`（31081 B）都实测无匹配。原实现中的首页提取逻辑保留为
兼容其它部署的兜底。

`project.id` 固定 `1`（本科）。

### 2.3 课表请求

```
POST /eams/courseTableForStd!courseTable.action
body: ignoreHead=1&setting.kind=std&startWeek=&semester.id=<id>&ids=<ids>
```

### 2.4 课表响应结构（**已用真实样本逐位验证**）

```js
var table0 = new CourseTable(2026, 70);   // 70 = 7 天 × 每天 10 节
var unitCount = 10;                        // 每天节数
…
activity = new TaskActivity(teacherIds, teacherNames,
    "17808(26271.MK00001A.050)",           // arg2 课程代码
    "示例课程甲(26271.MK00001A.050)", // arg3 课程名(代码)
    "258",                                  // arg4 教室 id
    "X205",                               // arg5 教室名
    "00110000111111110000000000000000000000000000000000000", // arg6 周次串
    null, null, assistantName, "", "");
index = 1*unitCount+0;
table0.activities[index][table0.activities[index].length] = activity;
…
table0.marshalTable(2,1,20);
fillTable(table0,7,10,0);
```

**四个关键编码（**曾列为未知量，现已由样本 + 渲染表交叉验证钉死**）**

| 量 | 含义 | 证据 |
|---|---|---|
| `index = i*unitCount + j` 中的 `i` | **星期索引，0=周一 … 6=周日** | 单元格 id `TD0_0`/`TD10_0`/… 依次落在 星期一…星期日 列头下 |
| `j` | **节次索引，j = 节次 − 1**（j=0 即第一节） | 行标签「第一节」下的单元格全为 `TD*0_0` |
| `vaildWeeks[p]` | **第 p 教学周**（p 从 1 起有语义；第 0 位恒为占位 `0`） | 见下方三例 |
| 串长 | **53**（全年 53 周口径） | `TaskActivity.js` 注释「53代表53周」 |

**交叉验证三例（0/1 串 ↔ 页面渲染文字，逐位吻合）**

| 串（截断） | 位置 | 渲染文字 | 结论 |
|---|---|---|---|
| `0011000011111111000…` | 1×10+0（周二第一节） | 马克思 `(2-3 8-15)` | weeks 2,3 + 8–15 ✓ |
| `0111000011111111100…` | 4×10+0（周五第一节） | 马克思 `(1-3 8-16)` | weeks 1,2,3 + 8–16 ✓ |
| `0111000011010101000…` | — | 示例课程乙 `(1-3 8-9 单11-15)` | weeks 1,2,3 + 8,9 + 11,13,15 ✓ |

> **单双周不需要单独推断** —— 0/1 串已按周显式编码（上例第 10、12 位为 `0` 即为「单周」效果）。这是本方案比「解析渲染后的表格文字」更稳的根本原因。

**样本实况**：31 条 `TaskActivity`、14 门课、最大用到第 18 周、教室含「示例场馆」「示例场地」「X106(示例实验室)」等非规范名。

### 2.5 写入侧：**零改动**

`lib/data/import_export/timetable_import_export.dart` 的
`importJson(String content, {int? targetSemesterId, required ImportStrategy strategy})`
吃 `{semester, periods, courses}` 三段 JSON，已具备严格校验、事务写入、整表替换节次、overwrite/merge 两种策略。

→ 本功能**只需产出那个 JSON 字符串**。`plai-data` 一行不用改。

## 3. 数据缺口与降级

| 缺口 | 页面里有没有 | 处理 |
|---|---|---|
| **开学日**（`Semester.startDate`） | ❌ 无 | 先探 `dataQuery.action` 自动取；取不到 → **降级为导入页手填**（硬需求，缺它日期全错） |
| 学期名 | ❌ 无 | 导入到当前学期，**不需要** |

| **节次起止时间** | ❌ 无（只有 10 个节次序号） | **沿用 Plai 默认模板前 10 节**。学校结构（上午4/下午4/晚上2）与模板 1–10 完全吻合 |

```
  eams_import_service.dart 编排：记账式清理 + 调用 importJson + 记账写回

  eams_parser_test.dart
  eams_client_test.dart
  eams_import_service_test.dart
  fixtures/                 解析样本（见 §6.2）
```

**分层纪律**：网络层与解析层**严格分离**。解析层是**纯函数**，不碰网络、不碰数据库，用真实样本做单测 —— 学校改版只需改这一层。

**Cookie 处理**：手写约 40 行 cookie jar（只有 `JSESSIONID` + `GSESSIONID` 两个），**不引入新依赖**（`http` 与 `crypto` 均已是现有依赖）。

## 5. 导入编排：记账式（关键设计）

### 5.1 为什么不用单纯的 merge

现有 merge 的去重键实测为：

```sql
WHERE semester_id = ? AND name = ? AND weekday = ?
  AND start_week = ? AND end_week = ? AND start_period = ? AND end_period = ?
```

**不含教师、教室、颜色、weekList**。于是：

| 教务侧发生什么 | 纯 merge 的后果 |
|---|---|
| 换教室 / 换老师 | 键未变 → 跳过，**永远看不到新教室** |
| 改周次 | 键变了 → **新增一条，旧的还在 → 重复课** |
| 删课 | Plai 里留着，**永不清理** |

### 5.2 记账式流程

```
① 读 setting「eams.imported_ids.<学期id>」= 上次导入写入的课程 id 集合
② 删除这些 id 中仍然存在的课程        ← 手动课不在记账里，结构上碰不到
③ importJson(…, targetSemesterId: 当前学期, strategy: merge)
                                      ← merge 顺带与手动课同键去重
④ 导入前后各取一次 getCourses(学期id) 的 id 集合
   差集 = 本次新增 → 序列化写回 setting
```

- **零数据层改动**：`importJson` 签名不变；步骤 ④ 用前后差集实现（单线程，无竞态）
- **用户手动添加的课从未进入记账 → 结构上不可能被删或改**，这是用户要的硬保证
- 重复导入不再重复；教务侧的改名/改教室/改周次都能正确同步

### 5.3 开学日冲突（用户已确认的处理方式）

开学日属于**学期**，不属于单条课程。若自动推导的开学日与当前学期不一致，改它会连带改变**该学期全部课程**（含手动的）—— 与决策 4 直接冲突。

**处理（默认最保守）**：预览页并排显示两者，不一致即橙色警告，**默认不勾、不自动改**：

```
Plai 当前学期：  开学日 2026-09-01 · 共 16 周
教务侧推导：     开学日 2026-09-07 · 共 18 周   ⚠️ 不一致

[ ] 同时更新本学期的开学日与总周数
    （勾选会改变该学期全部课程的日期，包括你手动添加的）
```

## 6. 测试计划

### 6.1 测试点

1. **解析层**（M1）：真实样本 → 断言 Activity 条数、抽样比对「0/1 串 → 周次集合」（必须含单双周那条 `示例课程乙`）、周次集合 → `every`/`odd`/`even`/`custom` 归类
2. **网络层**（M2）：salt 提取、`SHA1(salt-密码)` 拼接、`actionError` 失败识别、Cookie 串联
3. **编排层**（M3）：记账键读写、前后差集、手动课程不被触碰、重复导入不重复
4. **UI**（M4）：三态、密码不落盘、开学日冲突警告
5. **回归**：`flutter analyze` 无告警 + `flutter test` 全绿

### 6.2 ⚠️ 样本策略（**必须按此执行，踩过坑**）

`AGENT_ONBOARDING.md` §6.5 的教训：**验证步骤本身不得对被测对象做归一化/清理**。据此：

- **仓库内 fixture**：只剥掉浏览器插件注入的 `<plasmo-csui>` 节点（那 5MB 是**插件产物、不属于服务端响应**）。剥它不是「简化被测对象」，而是**让 fixture 更贴近生产输入**（生产里 parser 吃的是 HTTP 响应体，从来不含插件 DOM）。其余字节保持原样。
- **脱敏**：fixture 里的学号、姓名、课程名、教师名替换为等长的假值，**保持结构与字段长度不变**。仓库是公开的（GitHub `JiShuai-183/Plai`），不宜提交本人的课表实况。
- **独立验证**：实施期**另外**用**未脱敏的原始真样本**跑一次解析，与其结果做人工抽检对账 —— 这是唯一能证明「脱敏没改变行为」的证据。该次运行的结论记入提交说明，原始样本**不提交**。

### 6.3 真机验证（发布前）

解析正确性最终以**用户手上的真实课表**为准：导入后逐格比对课表页与教务页截图。

## 8. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | **明文 HTTP 不可避**（HTTPS 实测不通）。密码 SHA1 摘要**等价于密码**，中间人可重放 | 只对该域名开明文，不全局 `usesCleartextTraffic`；不引入任何第三方中转；在导入页明示用户该连接为明文 |
| 2 | **账号锁定**（教务系统常见「密码错 N 次锁号」） | **绝不自动重试**，错一次即停并提示 |
| 3 | 学校改版 → 解析失效 | 解析层纯函数 + 真实样本单测；改版只改一层 |
| 4 | 教务偶发无验证码但后续会出 | 检测到验证码元素即停并提示用户，不硬闯 |
| 5 | 导入到当前学期，若两边开学日不同会静默错位 | §5.3 的并排警告 |
| 6 | 记账键与用户手动删除课程交互 | 删除时 id 已不存在 → 跳过，无副作用 |
| 7 | 样本文件含个人身份信息 | §6.2 脱敏 + M0 加 `.gitignore` |
| 8 | 排课含非规范教室名（示例场馆 / 示例场地） | 原样写入 `location`，不做校验 |
